# RVG Gateway on Reflex (Build / Cloud)

Structure (matches the Reflex Build file tree):

    app/__init__.py
    app/app.py        <- Reflex entrypoint (api_transformer + lifespan + landing page)
    app/rvg/          <- original RVG source, untouched (main.py, pages.py, protocol/, ...)
    assets/           <- favicon.ico, placeholder.svg
    apt-packages.txt  <- build tools for the MTProto binary
    requirements.txt
    rxconfig.py       <- app_name="app"

`reflex.lock/` (bun.lock, package.json) is generated by Reflex on the first build — not included.

## Secrets to set (Reflex Build -> Secrets)
- `REDIS_URL`  strongly recommended: local disk is wiped on restart, RVG then keeps links/quotas in Redis.
- `SECRET_KEY` optional.

## First checks after deploy
1. `https://<app>/ping`        -> "pong"   (Reflex backend)
2. `https://<app>/health`      -> {"status":"ok",...}   (RVG route; proves custom backend routes are reachable)
3. `https://<app>/login`       -> RVG panel
4. import a link in v2rayNG and connect (`/ws/<uuid>` must accept WebSocket upgrades)

If 2 fails while 1 works, the platform only forwards Reflex's own routes to the backend.
